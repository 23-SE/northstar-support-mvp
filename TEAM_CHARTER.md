## 2. Communication

- **Primary channel:** WhatsApp group (quick coordination) + GitHub (code, PRs, issues).
- **Expected response time:** within **2 hours** during working hours (09:00–22:00 EAT).
- **Daily check-in:** a short written status in the group — *what I did / what's next / any blockers*.
- **Blockers:** flag in the group **immediately** — do not sit on a blocker for more than 1 hour.

## 3. Deadlines & Workflow

- Hard deadline: **15 Aug 2026, 11:59 PM EAT** (all assignments).
- **Branch per person**, named `feat/<area>-<name>` (e.g. `feat/returns-grace`). No direct commits to `main`.
- **Commit convention (enforced):** `<type>: <what changed> - <why it matters>`. `wip`/`updates` are **not** acceptable.
- **Board status moves the same day** the work is done — no batched end-of-day/-week updates.
- Merge to `main` via Pull Request; another member gives a quick review where possible.

## 4. Definition of Done (team-wide)

A task is Done when: the code runs locally without errors, it matches the shape in `API_CONTRACT.md`, the board card is moved to Done, and the branch is merged (or PR opened) with a proper commit message.

## 5. Conflict Resolution

1. Discuss in the group chat and try to reach consensus.
2. If unresolved, the **Team Lead** makes a timeboxed call so work isn't blocked.
3. Decisions that change scope or architecture are noted in the PR description for the record.

## 6. Accountability / Escalation

- **Zero visible activity for a full day** (no commits, no board moves, no messages) triggers a direct check-in from the Team Lead — not a wait-until-deadline.
- Everyone makes **at least one real commit** so the audit log shows genuine, balanced contribution.
- The Peer Reliability Index (Assignment 3) is **confidential**; only aggregate patterns are discussed, never verbatim.
